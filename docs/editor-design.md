# G.O.M.I エディタの設計(UI を詰める)

2026-11-08 作成。コンセプト → 差別化 → 機能の洗い出し → 配置 → UX の見直し の順に決める。決まったことはこの文書を更新する。

## 1. コンセプト

**「AI と作れて、毎回同じ結果を出せるエンジン」**

- 使う人: 自分(C++ も JSON も読める)。説明より速さと情報量を優先する
- 人がエディタで組み立てて仕上げ、AI(Claude Code など)は JSON とコマンドで作って、操作の再現と画面の比較で確かめる。両方が同じシーンファイルを触る

## 2. ゲームエンジンとしての差別化

Unity・Godot と機能の量では並ばない。次の 4 つに絞って尖らせる。

| 軸 | G.O.M.I | 一般的なエンジン |
|---|---|---|
| テキストが正 | シーン・プレハブ・UI がすべて短い JSON。変えた所だけ overrides。差分が読める | バイナリや長い YAML。差分を読む前提ではない |
| 毎回同じ結果 | 固定Δt・操作の記録と再生で、同じ入力から同じ画面が出る | 物理や時間で結果が揺れる。再現は自前で作る |
| 確かめるのが標準 | 記録した操作を流し、基準の画面と比べる「再現テスト」をエディタとコマンドの両方に持つ | テストは別のフレームワーク。画面比較は外部ツール |
| 全部コマンドで動く | エディタの操作はすべて名前付きのコマンド。起動オプション・コマンドパレット・(将来)AI からの呼び出しで同じものを使う | GUI 前提。自動化は一部の API |

捨てるもの: 見た目の豪華さ、多数のプラットフォーム、ノードの視覚的スクリプト、アセットストア。

## 4. 必要な機能の洗い出し

優先度: P0 = コンセプトの柱か、無いと日常的に困るもの / P1 = あると速い / P2 = 後で

### コンセプトの柱(再現・比較・テキスト・コマンド)

| 優先 | 機能 | 中身 |
|---|---|---|
| P0 | 再生の制御 | 一時停止・1 フレーム送り・固定Δt(既定 60)・フレーム番号の表示 |
| P0 | 操作の記録と再生 | 再生中の入力をフレーム番号付きで `tests/replays/*.json` に書く。同じシーン・同じΔtで流し直すと同じ画面になる |
| P0 | 再現テスト | 記録に「確かめる点」(フレーム番号)を付け、基準の画面・状態(JSON)を保存。流して比べ、合否と違う所(画像の差分・変わった項目)を出す。ゲームの起動オプションでも同じことができる(CI・AI 用) |
| P0 | ファイルの変更を読み直す | assets の JSON が外で変わったら読み直す。エディタ側に未保存の変更があれば確認する |
| P0 | 変更の差分 | 保存済みのファイルと今の状態の JSON の差を、Entity・コンポーネント・項目の単位で見せる |
| P0 | コマンドパレット | Ctrl+Shift+P で全操作を名前で探して実行。メニュー・ショートカット・起動オプションと同じ名前 |
| P1 | フレームの巻き戻し | 記録の再生中に、決めた間隔で状態を覚え、時間を戻して見られる |
| P1 | 状態の書き出し・貼り付け | 選んだ Entity を JSON としてコピー/貼り付け(AI とのやりとり用) |
| P2 | AI からの操作口 | エディタのコマンドを外から呼べる口(MCP サーバ)。AI が開いているエディタを動かせる |

| 優先 | 機能 | 中身 |

## 5. 配置

```
┌ メニュー ──────────────────────────────────────────────────────────────┐
├ ツールバー: [▶ 再生][⏸][⏭ 1コマ][● 記録] Δt 1/60 | [移動][回転][拡大] | カメラ: エディタ/ゲーム | scenes/Field.json* ┤
├────────────┬───────────────────────────────────────────┬──────────────────┤
│ヒエラルキー │ シーン                                     │ インスペクタ      │
│ [検索]     │                                           │ 作るための値      │
│ ・Camera3D │        (ゲームの画面)                       │ ▸ 実行時の値      │
│ ・player   │                                           │   (再生中だけ)    │
│ ・crate #1 ├───────────────────────────────────────────┤                  │
│ ・crate #2 │ 時間の帯: ├──●───▲────▲──┤ フレーム 240/600 │                  │
├────────────┴───────────────────────────────────────────┴──────────────────┤
│ 下段タブ: [再現テスト] [差分] [アセット] [System] [ログ]                     │
├──────────────────────────────────────────────────────────────────────────┤
│ 状態バー: 停止中 | フレーム 0 | 60 FPS | 選択: player | 未保存 3 件 | ⚠ 最後のエラー │
└──────────────────────────────────────────────────────────────────────────┘
```

- 中央の下に「時間の帯」: 記録を流している時だけ出る。● は今、▲ は確かめる点(赤は不合格)
- 下段の最初のタブは「再現テスト」(コンセプトの柱を常に目に入る所に置く)
- 状態バーは常に表示。エラーが出たら赤くなり、押すとログを開く
- 再生中は窓の枠とツールバーをオレンジにする

## 6. UX の見直し(方針)

- **押す前に結果が分かる**: 再生中の変更は消える・保存すると overrides になる、などを操作の場所に出す
- **ショートカットは窓の外でも効く**: W/E/R はシーンの上でなくても(文字入力中を除き)効くようにする
- **同じ名前で呼べる**: メニュー・コマンドパレット・起動オプション・(将来の)AI 操作で、コマンドの名前を揃える
- **説明は最小限**: 使うのは自分なので、長い説明文は置かない。ツールチップに寄せる
- **失敗は目に入る所に**: ログ欄に隠さず状態バーに出す
